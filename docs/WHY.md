# Tickpack — 这个项目最有趣的那一刻

> 写于 2026-10-26，第一次动手前。这是我的承诺，不是需求文档。

**那一刻：你写下 6 行循环，按下 Run，然后看见「循环变成了时间」。**

左边是一段程序，右边是生成的 mcfunction。中间的方块世界里，笔尖一格一格地走，
每走一步，`over 8 as i` 里的 `i` 就加一，屏幕上对应的一行 mcfunction 亮起来。
循环不是「一口气跑完」，而是**每个 tick 迭代一次**——一行 `over` 在数据包里
真的就是一个记分板计数器加一个程序计数器，你能在计分板面板里亲眼看到
`i: 0 → 1 → 2 …`。C 程序员的直觉说「循环是瞬时的」，Tickpack 说「循环就是时钟」。

第二个「哦——」：底部那条时间轴。程序跑完后往回拖，世界倒带，方块一个一个消失，
生成出来的代码行也跟着往回走。**时间成为可以触摸的一等公民。**

所以这个项目要做的，是让「tick」这个东西看得见、摸得着、能玩：

- 程序里所有跨越时间的控制流（`over`、`wait`）都编译成显式的状态机 + 记分板，
  不是解释器魔法；
- 模拟器里的世界由**编译出来的 mcfunction** 驱动，不是另一套并行的解释器；
- 浏览器里三样东西同屏、同步：源码 / 生成的数据包 / 正在跑的世界；
- 最爽的用法：改几行代码，让乌龟画一个只属于你的图案，然后下载成一个真的
  能丢进 Minecraft 存档的数据包。

**如果哪天做的东西不再通向这一刻（比如在补一门语言的所有边角、在做一个通用
可视化编辑器），就停下来，回来看这段话。**

## 决定记录

| 日期 | 选了什么 | 放弃了什么 | 为什么 |
| --- | --- | --- | --- |
| 2026-10-26 | 语言的核心语义是「控制流跨 tick、状态=记分板」，`over` 每次迭代消耗 1 tick | 把 tick 当成普通语言里的一个库函数 / 宏 | 「循环变成时钟」是最直接的「哦——」，也是和 mcfunction 模型真正同构的地方 |
| 2026-10-26 | 模拟器直接执行编译产物（mcfunction 文本子集），不执行 AST | 写一个高效的解释器 | 保真 = 看到的就是数据包会做的事；也逼编译器产出可读的代码 |
| 2026-10-26 | 世界 = 33×33 平面 + 一只笔（armor stand, tag=pen），内置 turtle 风格标准库 | 一开始就做通用方块世界 / 红石 / 实体物理 | 立刻能画东西、能分享图案，且生成的命令是真的 Minecraft 语法 |
| 2026-10-26 | 函数是编译期宏（常量参数直接替换进 `run` 行），只有时间轴上的代码才生成状态机 | 完整函数调用栈、运行时参数、闭包 | 用极小的代价换来漂亮的标准库（`plot(gold_block)`、`turn(45)`），不干扰核心的 tick 语义 |
| 2026-10-26 | 交互只有一条主线：写代码 → Run → 逐 tick 看 → 拖时间轴回放 | 积木编辑器、菜单、账号、存档系统 | 先把「循环变成时间」这一个瞬间做到极致；积木如果做，必须和文本共享 AST，留到下一刀 |
| 2026-10-26 | 调度器加 `#__b` latch（每个状态函数入口清 0，dispatch 只放行一个） | 规范的「一行 dispatch」写法 | Minecraft 顺序执行函数行，状态函数会在 dispatch 返回前改 `#__pc`；没有 latch 一个 tick 会推进两个状态。可观察语义不变 |
| 2026-10-26 | 时间轴每个 tick 存整份快照，拖动即恢复 | 增量 diff / 只重放 | 33×33 世界很便宜；回放/倒带是「时间是第一公民」的手感，值得用内存换 |
| 2026-10-26 | 一键下载真的 `.zip`（自己写 store-only zip writer） | 只显示文件树 / 只复制单文件 | 「能发给朋友、能丢进 Minecraft」比「看起来像工具」重要，且零依赖 |
| 2026-10-26 | 示例从「黄金角花瓣」换成「五角星 / 圆」 | 保留数学上更酷但画面上是个小点的花瓣 | 用真实的编译器+模拟器跑了 ASCII 预览；示例首先要**好看**，其次才是有教学意义 |
| 2026-10-29 | 画笔锚定到玩家脚下（`execute at @p run summon ... ~ ~-1 ~`），并且**等主世界里有玩家才开始** | 固定在世界原点 `(0.5, 0, 0.5)`、世界加载时直接跑 | 真实测试：数据包装进 1.21.1 后什么也看不到——y=0 在超平坦世界里是地面以上 60 格，而且程序在玩家进世界之前 2 秒就画完了。宁可等玩家，也要让他亲眼看到 |
| 2026-10-29 | 开始/重画/状态用聊天栏 + `/function tp:start` / `tp:status` 显式反馈 | 静默运行 | 真实测试里「没装好」和「在跑但看不见」表现完全一样；一行聊天消息就能区分。没有反馈的玩具看起来像坏的 |
| 2026-10-29 | `pack.mcmeta` 加 `supported_formats`（48..9999） | 只写 `pack_format: 48` | 用户是 1.21.1（48 本身没错），但未来 1.21.x 不应该因为格式号被标成 incompatible；装错目录时也更少一层困惑 |
| 2026-10-29 | README 把「放进存档 datapacks/，不是 resourcepacks/」写在最显眼的位置，并加排障清单 | 假设用户知道数据包放哪 | 第一次真实安装就放进了 resourcepacks/。这不是用户的问题，是文档的问题 |
| 2026-10-29 | 运行时画笔：`brush(block)` 编译成 `#__brush` 调色板下标，`paint` 走一次 dispatch；另外生成 `/function tp:brush/<block>` ×12 + `brush/next` | 只让 `plot(块)` 在源码里写死；或给每个程序生成独立 setblock 变体 | 用户在真实游戏里想换颜色，不想每次回网页重编译。一个记分板 + 10 来行 dispatch，就换来「游戏里随时换笔」 |
| 2026-10-29 | 起始坐标用 `/execute positioned X Y Z run function tp:start_at`（执行位置就是作画层） | 给函数加宏参数（`/function tp:start_at {x:…}`）或让用户站在目标点 | 不引入 macro 函数/存储参数，普通玩家也能用；而且和开始/重画共用一套 rewind，语义不分裂 |
| 2026-10-29 | 加 `#__paused` + `/function tp:stop` | 用 `#__started=0` 表示暂停 | 自动开始的门条件是 `started==0 && 有玩家`，单纯把 started 清 0 会立刻被重新启动；显式 paused 才能真的停住（尤其对 tick-only 的无尽程序） |
| 2026-10-29 | world 视口不再限制 33×33：默认自动框住全部内容，滚轮缩放、拖动平移、双击/F/fit 适配，暂停/完成/拖时间轴时立即框好 | 固定 33×33 画布 + 只做窗口内缩放 | 用户原话「每次都显示不全」；画得比 33×33 大是正常需求。相机适配是玩具能不能玩下去的问题，不是装饰 |
| 2026-10-29 | 「无尽螺旋」示例改成 tick 驱动的扩张方形螺旋（每 4 tick 一格） | 匀速转 91° 的「无尽涂鸦」 | 等步长 + 等转角必然画出闭合正多边形（实测只剩 4 个方块原地打转）；用 state 让臂长递增，图案才会一直长大 |
