# Tickpack 3D 坐标与正交投影（排期备忘）

> 状态：**已排期，未开工**。排在 **P0.5（particle / sound）之后、UI P1/P2 之前**。
> 原因：3D 会同时改语言坐标、模拟器世界模型、编译器 prelude 和 World 渲染；先做 UI P1 的键盘/对比度会在 3D 世界视图上返工。P0.5 是最后一个低风险的小功能，做完就进 3D。

## 0. 目标

把 Tickpack 的“世界”从 `x,z` 平面扩展成 `x,y,z` 三维：

- 语言仍默认 2D（y=0），现有示例、分享链接、数据包行为不变；
- 新增垂直方向能力后，同一套源码在浏览器正交投影世界和 Minecraft 里同步执行；
- 模拟器使用**正交投影**显示 3D 方块（不是透视），支持缩放/平移/旋转视角；
- 时间轴、快照、粒子、声音、数据包 trace 仍按 tick 同步。

## 1. 语言与 prelude

候选 API（开工时定稿，避免名字反复改）：

```
fn up(n)        # 笔上升 n 格（y += n）
fn down(n)      # 笔下降 n 格
fn pitch(deg)   # 改笔的俯仰角；walk 使用 ^ ^ ^1，所以会沿视线走
```

- 现有 `walk`/`turn`/`paint`/`plot` 不变；默认 y=0、pitch=0，2D 程序逐字节兼容。
- `paint`/`plot` 仍用 `~ ~ ~` / `^ ^ ^` 的 3D 坐标；编译器不需要重写坐标系统。
- 真实 Minecraft 用 armor stand 的 yaw/pitch；`up/down` 直接 `tp @s ~ ~$n ~`，`pitch` 设置 `~ ~` 或 `~$deg` 的第二个旋转参数（开工时验证 1.21 命令语法）。
- 新增示例：金字塔/塔/多层像素画，至少一个能证明“同一份源码在浏览器和 Minecraft 都是 3D”。

## 2. 模拟器

- 世界已经是 `Map<"x,y,z", block>`；主要工作在 **pen 状态**（加 y/pitch）、局部坐标移动、`contentBounds` 三轴、快照兼容（缺 y 的旧快照按 0）。
- 正交相机：`{yaw, pitch, zoom, cx, cy, cz}`；默认 2D 兼容视角（俯视、pitch=90° 或等价），3D 示例可用等轴视角。
- 渲染：按相机基向量投影方块顶点，画家算法/按深度排序绘制立方体；正交投影不做透视缩放；选中/悬浮/画笔标记也要投影。
- 交互：滚轮缩放、拖动平移、双击适配全部三轴；可选用右键/快捷键旋转视角；时间轴 seek 仍只还原快照，不插值。
- 自动适配：bounds 包含 x/y/z 与 pen；默认 2D 程序仍框在原来的 33×33 平面。

## 3. UI / 数据包 / 测试

- World 面板的 view readout 增加 y；适配按钮、缩放、CSS/DPR（v0.1.1 的修复）继续有效。
- 粒子/声音事件已是 3D 坐标；世界渲染的粒子也要按相机投影。
- 数据包：预置/示例的 `execute` 命令仍是 3D；`tp:start`/`home` 的 y 行为开工时检查。
- 测试：语言编译（新 prelude）、sim 3D 移动/投影数学、快照 round-trip、2D 回归、示例编译；Edge 截图覆盖 2D 回归 + 3D 示例 + 时间轴。
- 文档：LANG §4/§6、WHY、README、版本说明。

## 4. 版本与验收

- 版本：**v0.4.0 · 3D 正交投影**（P0.5 完成后打 v0.3.0）。
- 验收（能玩的最小切片）：
  1. 现有 2D 示例在默认视角下与现在视觉一致；
  2. 新 3D 示例在浏览器显示正交立方体，拖时间轴可回放，缩放/平移/适配正常；
  3. 同一示例导出数据包在 Minecraft 1.21 画出 3D 结构；
  4. particle/sound、分享链接、单文件、Pages 不回归；
  5. 全部测试 + 1440/1280/1024 截图。
- 若 3D 渲染阻塞（深度排序/交互），先交付“固定等轴视角 + 缩放/平移”的可玩切片，再做自由旋转；自由旋转不属于第一版必要条件。
